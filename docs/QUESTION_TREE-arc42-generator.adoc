== Q1 — What problem does this bounded context solve, and for whom?

=== Q1.1 Product identity

==== Q1.1.1 What does the program produce?
[ANSWERED] ZIP archives, one per (language, flavor, format) triple, named
`arc42-template-<LANG>-<STYLE>-<FORMAT>.zip`.
Evidence: `lib/Packager.groovy:83`; target directory `buildconfig.groovy:38`.

==== Q1.1.2 From what input?
[ANSWERED] A single AsciiDoc "Golden Master" per language: one main file plus a chapter
directory plus images plus a version file.
Evidence: `lib/Templates.groovy:213` (`arc42-template.adoc`), `lib/Templates.groovy:231-234`

[ANSWERED] The template itself. The README opens by sending template users away to
arc42.org/download.
Evidence: `README.adoc:3`, `README.adoc:132-133`.

==== Q1.1.4 How large is the output space?
[ANSWERED] 17 formats × 2 flavors × discovered languages.
Evidence: `buildconfig.groovy:17-35` (17 format keys), `buildconfig.groovy:10-15` (`plain`,
`with-help`; `with-examples` commented out), `build.groovy:220-223` (the product is computed

==== Q2.6.1 BR-1 Language directory naming
[ANSWERED] A directory is a language exactly when its name matches `/^[A-Z]{2,}$/`. The rule is

Evidence: `lib/Templates.groovy:38`; `lib/Discovery.groovy:62`.

==== Q2.6.2 BR-2 Flavor definition
[ANSWERED] A flavor is a named list of features to keep; everything in `allFeatures` not listed
is stripped.
Evidence: `buildconfig.groovy:7-15`; subtraction at `lib/Templates.groovy:205`.

==== Q2.6.3 BR-3 Feature removal mechanics
[ANSWERED] Two mechanisms: delete `[role="arc42<feature>"]` delimited blocks; for `help` also
delete the `ifdef::arc42help[]` / `endif::arc42help[]` marker lines while keeping their body.
Evidence: `lib/Templates.groovy:80`, `:84-87`.

==== Q2.6.4 BR-4 Image policy by flavor
[ANSWERED] `plain` receives only `arc42-logo.png`; every other flavor receives all images.
Evidence: `lib/Templates.groovy:114-133`.

==== Q2.6.5 BR-5 Image policy by format
[ANSWERED] Images are copied only for formats whose `imageFolder` flag is true; `epub` is the
sole exception in the configuration. `mkdocs` variants receive them under `docs/images`.
Evidence: `buildconfig.groovy:18-34`; `lib/Converter.groovy:54`; `lib/Converter.groovy:282`.

==== Q2.6.6 BR-6 Include-path rewriting
[ANSWERED] On generation, `include::adoc/` becomes `include::` and `include::../common/` becomes
`include::../../../common/`; on AsciiDoc output, every `include::` gains a `src/` prefix.
Evidence: `lib/Templates.groovy:68`, `:71`; `lib/Converter.groovy:265`.

==== Q2.6.7 BR-7 Russian LaTeX font encoding
[ANSWERED] LaTeX output for RU adds `fontenc=T1,T2A`.
Evidence: `lib/Converter.groovy:195-197`.

==== Q2.6.8 BR-8 mkdocsMP page suppression
[ANSWERED] `config.md` and `about-arc42.md` are deleted from mkdocsMP output.
Evidence: `lib/Converter.groovy:348`.

==== Q2.6.9 BR-9 Flavor name normalisation in file names
[ANSWERED] Non-letters are stripped from the style for the ZIP name, so `with-help` becomes
`withhelp`.
Evidence: `lib/Packager.groovy:80`, used at `:83`.

==== Q2.6.10 BR-10 The declared but unused `example` feature

== Q4 — What quality goals drive the design?

Scenarios below use the six-part form where the code supplies a literal response measure. No
target number is invented; every figure is quoted from the repository.

=== Q4.1 Functional suitability
[ANSWERED] Stimulus: a full build. Response: every discovered language is generated in two
flavors and 17 formats. Measure: 18 templates and 306 conversions for nine languages, computed
and printed by the build itself.
Evidence: `buildconfig.groovy:17-35`; `build.groovy:220-223`; measured run `TEST-REPORT.md:119`.

=== Q4.2 Performance efficiency
[ANSWERED] Stimulus: full HTML build of 18 templates on a developer machine. Response: pipeline
completes. Measure: 17.4 s total, 10.7 s template generation, 0.6 s packaging.
Evidence: `TEST-REPORT.md:365`, `:102`, `:274`; mechanism `lib/Converter.groovy:429`.

=== Q4.3 Compatibility
[ANSWERED] Stimulus: a Markdown consumer parses the output. Response: the file parses as
CommonMark. Measure: `cmark` exits 0 for every file in `build/EN/markdown`.
Evidence: `build-arc42.sh:94-104`; format-level compatibility via the DocBook pivot
`lib/Converter.groovy:69-70`.

=== Q4.4 Interaction capability (usability)
[ANSWERED] Stimulus: a maintainer wants all outputs. Response: one command. Measure: a single
`docker compose up`, or one `groovy build.groovy` with an optional phase and format filter.
Evidence: `docker-compose.yml:9`; `build.groovy:16-21`; progress line per conversion
`lib/Converter.groovy:436`.

=== Q4.5 Reliability
[ANSWERED] Stimulus: one conversion fails. Response: the remaining conversions still run and the
failure is reported. Measure: failure is isolated to one (template, format) pair; the run
continues and validation failures are declared non-fatal.
Evidence: `lib/Converter.groovy:74-78`; `build-arc42.sh:109-111`, `:187-188`; retry only for the
submodule `build-arc42.sh:66-78`.

=== Q4.6 Security
[ANSWERED] Stimulus: the Golden Master contains a hostile include. Response: it is executed.
Measure: `SafeMode.UNSAFE` on all three AsciidoctorJ call sites, `safe.directory '*'` in the
image, and no checksum on any downloaded binary.
Evidence: `lib/Converter.groovy:100`, `:132`, `:311`; `Dockerfile:61`; `build-arc42.sh:39-41`.

=== Q4.7 Maintainability
[ANSWERED] Stimulus: add a language versus add a format. Response: the first needs no code, the
second needs three edits. Measure: language discovery is regex-driven at
`lib/Templates.groovy:38`; a format touches `buildconfig.groovy:17-35`,
`lib/Converter.groovy:60-71` and `lib/Converter.groovy:382-398`.
Evidence: as cited; procedure documented at `CLAUDE.md:170-181`.

=== Q4.8 Flexibility / portability
[ANSWERED] Stimulus: run on amd64, arm64, macOS, Windows or Codespaces. Response: the same
pipeline runs. Measure: architecture-specific Pandoc package selection, LF normalisation for
scripts, and a Codespaces permission declaration.
Evidence: `build-arc42.sh:23-36`; `.gitattributes:2-7`; `.devcontainer/devcontainer.json:4-9`.

=== Q4.9 Which characteristic has priority?
[OPEN] Category: quality-goals. Ask role: Architect.
The code guards performance and functional suitability with measurements, and leaves security
and reliability to defaults. Whether that ranking is intended or accidental cannot be read from
the code.

==== Q5.1.7 Untyped data model
[ANSWERED] All inter-class data is passed as `Map`, so a renamed key fails at runtime, not at

Evidence: `lib/Discovery.groovy:127-140` consumed at `lib/Converter.groovy:86`, `:95`, `:157`.

=== Q5.2 Security risks

==== Q5.2.1 Unsafe AsciiDoc processing

==== Q5.2.2 Unverified binary installation

=== Q5.3 Operational risks

==== Q5.3.1 Destructive submodule refresh
[ANSWERED] The containerised pipeline deletes the whole `arc42-template` directory before
re-initialising it, so uncommitted local template work is lost.
Evidence: `build-arc42.sh:57-60`.

==== Q5.3.2 Green build despite failed conversions
[ANSWERED] Conversion failures are counted but the process still exits 0 and prints
"BUILD SUCCESSFUL".
Evidence: `lib/Converter.groovy:437-440`; `build.groovy:211-215`.

==== Q5.3.3 Silent no-op on a mistyped phase
[ANSWERED] An unrecognised phase runs nothing and reports success.
Evidence: `build.groovy:46` with guards at `:129`, `:145`, `:168`, `:185`.

==== Q5.3.4 No automated pipeline
[ANSWERED] No CI configuration exists, so nothing runs the test suite or the build on push.
Evidence: no `.github` directory in the repository; requirement
`docs/arc42_build_process_requirements.md:229`.

==== Q5.3.5 Release requires manual push into the submodule
[ANSWERED] Artifacts are written into the submodule working tree and must be committed there by
hand.
Evidence: `buildconfig.groovy:38`; `build-arc42.sh:200-204`.

=== Q5.4 Dependency and supply-chain risks

==== Q5.4.1 Runtime dependency resolution
[ANSWERED] Grape resolves AsciidoctorJ, the diagram extension and GPars when the script starts,
so a repository outage breaks the build outside Docker.
Evidence: `lib/Converter.groovy:3-5`; `lib/Packager.groovy:3`.

==== Q5.4.2 No lockfile, no checksums
[ANSWERED] Versions are pinned in four separate places and nowhere verified.
Evidence: `lib/Converter.groovy:3-5`; `init-groovy-deps.groovy:3-5`; `Dockerfile:23`;
`build-arc42.sh:26-27`.

==== Q5.4.3 Moving upstream inputs
[ANSWERED] The build checks out `master` of the template and pulls, so the output depends on
whatever upstream contains at build time rather than on the recorded submodule commit.
Evidence: `build-arc42.sh:69`.

==== Q5.4.4 Duplicate version pins that can drift
[ANSWERED] The same three Grape coordinates appear in two files and must be changed together.
Evidence: `lib/Converter.groovy:3-5` and `init-groovy-deps.groovy:3-5`.

=== Q5.5 Scaling and performance risks

==== Q5.5.1 Parallelism is one-dimensional
[ANSWERED] Only the template loop is parallel; the 17 formats of one template run sequentially,
so speed-up is capped by the number of templates, not by cores.
Evidence: `lib/Converter.groovy:430-432`.

==== Q5.5.2 Shared Asciidoctor instance across threads
[ANSWERED] One instance is created per `Converter` and used from every parallel worker.
Evidence: `lib/Converter.groovy:33` used at `:106`, `:139`, `:313` inside the parallel loop
`:430`.

==== Q5.5.3 Coarse lock on the progress counter
[ANSWERED] Every worker synchronises on the same object to increment counters and print.
Evidence: `lib/Converter.groovy:433`; `lib/Packager.groovy:136`.

==== Q5.5.4 Repeated full image copies
[ANSWERED] Images are copied once per format per template, and again into the DocBook working
directory.
Evidence: `lib/Converter.groovy:54` with `:287-294`; extra copy at `:157-169`.

==== Q5.5.5 Growth limit of the current design
[OPEN] Category: future-direction. Ask role: Operations.
No figure exists for how many languages or formats the pipeline must still handle comfortably,
so the point at which one-dimensional parallelism stops being adequate cannot be derived.
